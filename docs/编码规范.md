# 编码规范

## 项目组织

本项目基于umi4开发，使用umi推荐的目录结构（<https://umijs.org/docs/guides/directory-structure>）。

### swagger

本项目使用Swagger作为API规范工具。根目录的swagger文件夹存放swagger的配置文件。

umi的openapi配置在`./config/config.ts`中。 **每个swagger配置具有单独的命名空间，如sys.json对用SYS命名空间。** _原先使用唯一的API命名空间，但之后出现定义冲突。_

```json
{
  requestLibPath: "import { request } from '@umijs/max'",
  schemaPath: join(__dirname, '../swagger/sys.json'),
  namespace: 'SYS',
  projectName: 'sys',
},
```

```sh
rm -rf ./swagger
cp -r /root/swagger/ .
npx max openapi
```

使用以上命令在`./src/services`目录生成对应API。

### docker部署

`Makefile`和`Dockerfile`文件，以及`docker`文件夹是用于项目部署。前端不进行修改。

### pages目录

1. 使用配置式路由

umi支持约定式路由和配置式路由。项目中使用了Ant Pro的`ProLayout`组件，用于快速提供标准布局，自动生成菜单。

而`ProLayout`和umi配合使用，umi会把config.ts中的路由自动注入到配置的layout中，可以免去手写菜单的烦恼。但也因此限制了项目必须**使用配置式路由**。

_其实可以使用约定式路由，但需要在运行时配置中编写patchRoutes，但复杂度随着项目变大而上升，综合考虑使用配置式路由。_

2. 使用约定式路由命名方式

虽然使用配置式路由，但采用约定式路由的方式安排文件层级结构和命名文件。写法参考<https://umijs.org/docs/guides/routes>。

3. 非路由文件

pages目录下的其他非路由文件（夹），推荐以\_开头命名，以方便区分，且能较好利用编辑器中explorer的排序。

### root-container

`src/components/root-container.tsx`是项目的最顶层组件，用于第三方库相关的配置和系统的部分初始化。

## 命名规范

术语解释

- 短横线：形如`hello-world`
- CamelCase：形如`helloWorld`
- PascalCase：形如`HelloWorld`

1. 严禁用拼音命名，用有含义的英文单词，不要缩写（JS中普遍使用的除外）。
2. 文件名使用短横线作为常见扩展文件名。例如，resizable-filter-list.tsx
3. 组件命名使用文件名的PascalCase形式作为组件名称。例如，resizable-filter-list.tsx应该有一个引用名称ResizableFilterList。但是，对于目录的根组件，请使用index.jsx用作文件名并使用目录名称作为组件名称。
4. 引用命名React组件使用PascalCase，实例使用CamelCase。
   ```
   import ResizableFilterList from './resizable-filter-list.tsx'
   const list = <ResizableFilterList />
   ```
5. 方法命名使用CamelCase。
6. 变量命名使用CamelCase。
7. 常量命名，全字符大写，下划线分割，使用明确的单词，不嫌名字长。如， MAX_STOCK_COUNT。
8. interface命名，有些命名规则中要求interface命名加前缀`I`，没有必要，当作常规类型命名就行。

**React项目中typescript使用规范请参考<https://github.com/typescript-cheatsheets/react>。**

## 样式

### css文件

本项目采用[antd](https://ant.design/index-cn)作为主样式库，配合[tailwindcss](https://tailwindcss.com/)使用。尽量不要引入额外样式、组件库。

项目全局css文件有两个：`tailwind.css`和`src/globals.less`。

1. `tailwind.css`用于tailwindcss配置。

2. `globals.less`用于修改antd的样式。

**antd的全局样式使用ConfigProvider进行修改，位于`RootContainer`组件中。如果ConfigProvider中无法修改，才在globals.less中通过css选择器进行修改。**

除了这两个文件，**不要引入额外全局样式文件**，组件内的样式使用tailwindcss和CSS Modules（tailwindcss优先）。

### 暗色模式

项目目前没有适配暗色模式，但通过antd的ConfigProvider进行配置，能快速实现生效。为了之后的快速适配，文本颜色、背景色等颜色相关样式推荐使用antd的design token进行设置，参考<https://ant-design.antgroup.com/docs/react/customize-theme-cn>

## JS/TS 相关

1. 普通函数和箭头函数

最外层作用域中声明的函数推荐使用普通函数，内联函数、匿名函数推荐使用箭头函数。

2. null和undefined

避免使用null，能用undefined。（能商量）

3. 避免冗余的类型标注

多利用的ts的自动推导，不要额外进行类型标注，导致代码特别冗长，没有意义。

4. 禁止使用==比较符，只使用===

5. 默认导出不要使用匿名函数

## React 相关

### 函数式组件

1. **只使用函数式组件**，不要使用类组件（目前没有只有类组件才能完成的功能需求，需要的话再论）
2. 可选状态显性标注

```
const [error, setError] = useState<Error | undefined>()
```

3. useEffect单一职责，业务逻辑不要复杂
4. 使用useMemo和useCallback减少冗余渲染，但不要过度优化
5. 使用forwardRef包装组件时，使用displayName命名组件
6. 项目中使用react-query进行异步状态管理，不使用umi max自带的request
7. 不使用全局状态管理库（<https://tanstack.com/query/latest/docs/react/guides/does-this-replace-client-state>），如有必要，使用umi max的model。
8. 使用children，而不是props传递子组件（icon等除外）。
9. 不要直接使用useContext，使用自定义hook包装
10. 非必要不使用命令式导航
